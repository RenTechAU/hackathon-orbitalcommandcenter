The topology

Network & asset relationships as a graph

framework: FalkorDB · adapted to the ground segment

Their case: a Fortune 500 network provider runs a multigraph cluster of 60,000+ graphs — one per customer network topology — for live asset monitoring.

Ours: one subgraph per ground station, holding the satellites that can currently see it and the concessions between them. The topology changes every few minutes as satellites rise and set, so the graph is written continuously rather than loaded once.

The hidden graph problem

Our data is relational. Our question is graph-shaped.

framework: FalkorDB · adapted

  • Harder to evolve as the fleet grows
The question is a path

1 query · 1 traversal

Start at the dish, walk to who can see it, walk the YIELDED edges between them, and check the receiver is still in view. The relationships are the question — the answer was already in the shape of the data.

MATCH (g:GroundStation {name:$st})
  <-[:IN_VIEW_OF]-(giver:Satellite)
  -[y:YIELDED {station:$st}]->
  (recv:Satellite)-[:IN_VIEW_OF]->(g)
RETURN giver.name, recv.name, count(y)
